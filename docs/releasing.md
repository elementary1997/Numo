# Как выпускается Numo

## Каналы сборок

| Канал | Триггер | Что получается |
|---|---|---|
| **CI** (`ci.yml`) | каждый push/PR | analyze + тесты + web-сборка |
| **Автосборки** (`desktop-builds.yml`) | каждый push в `main` | артефакты Windows/macOS/Linux (14 дней), имя содержит SHA |
| **Релиз** (`release.yml`) | тег `vX.Y.Z` | GitHub Release с архивами всех трёх ОС |

## Выпуск релиза

1. Поднять `version:` в `pubspec.yaml` (например, `1.0.0+7`).
2. Убедиться, что `make check` зелёный, закоммитить и запушить.
3. Поставить тег и запушить его:

   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```

4. GitHub Actions соберёт Windows/macOS/Linux и опубликует Release с
   архивами и автосгенерированными release notes.

## Как пользователи узнают об обновлении

Приложение раз в сутки анонимно сравнивает свою версию с последним
GitHub Release (ADR-0010) и предлагает открыть страницу скачивания;
в Настройках → Обновления есть ручная проверка и выключатель
автопроверки. Поэтому **тег без поднятой версии в pubspec — ошибка**:
пользователи увидят «доступна версия», совпадающая с их собственной,
либо наоборот не увидят обновления. Версия в pubspec и тег обязаны
совпадать.

## Подписи и Gatekeeper

Сборки пока не подписаны сертификатами (Apple Developer / Authenticode):

- **macOS** блокирует первый запуск («не удалось подтвердить…»). CI
  ставит ad-hoc подпись (убирает «приложение повреждено» на Apple
  Silicon), а пользователю нужно один раз: правый клик → «Открыть» →
  «Открыть», либо `xattr -cr /Applications/Numo.app`. Полное решение —
  аккаунт Apple Developer ($99/год): тогда в CI добавляются секреты
  (сертификат Developer ID + notarytool app-password) и шаги
  codesign → notarize → staple; инструкция исчезает сама.
- **Windows** SmartScreen предупреждает о неизвестном издателе —
  лечится сертификатом Authenticode (или репутацией со временем).
