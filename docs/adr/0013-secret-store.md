# 0013. Секреты — в системном хранилище, не в shared_preferences

Дата: 2026-08-25
Статус: accepted

## Context

API-ключ LLM-провайдера (ADR-0011) хранился в shared_preferences — на desktop это незашифрованный файл на диске. Ключ даёт доступ к платному аккаунту пользователя у провайдера; это единственный настоящий секрет в приложении (PIN хранится как соль+хэш, ADR-0008; сами финансовые данные — тема отдельного решения о шифровании базы).

## Decision

Новая зависимость `flutter_secure_storage` (де-факто стандарт, покрывает все шесть платформ) за фасадом `lib/data/secret_store.dart`:

- **Носители**: Keychain (iOS/macOS), Keystore (Android), DPAPI (Windows), Secret Service/libsecret (Linux), WebCrypto (web — защита символическая, но не хуже прежней).
- **Фолбэк**: любая ошибка секьюрного хранилища (Linux без Secret Service, среда тестов) прозрачно уводит чтение/запись в shared_preferences — то есть в худшем случае поведение прежнее, регрессии нет.
- **Миграция**: при первом чтении значение из старого plaintext-ключа prefs переносится в секьюрное хранилище и удаляется из prefs; при недоступности хранилища остаётся в prefs до следующей попытки.
- **macOS**: используется легаси-кейчейн (`usesDataProtectionKeychain: false`), потому что data protection keychain требует entitlement «Keychain Sharing», недоступный ad-hoc подписанным сборкам (release.yml). После появления Apple Developer подписи можно перейти на data protection keychain.
- **Linux-сборки**: build-зависимость `libsecret-1-dev` добавлена в CI (desktop-builds.yml, release.yml).

Секретом считается только API-ключ. Endpoint, модель и имя провайдера остаются в prefs.

## Consequences

- Ключ больше не лежит открытым текстом там, где keychain доступен; где недоступен — честный фолбэк без падений.
- +1 зависимость с нативным кодом на всех платформах; Linux-сборка требует libsecret-1-dev.
- Юнит-тесты работают через фолбэк (плагина в тестовой среде нет) — секьюрная ветка проверяется вручную/в CI-сборках.

## Alternatives considered

- **Оставить как есть** — ноль затрат, но plaintext-секрет на диске у финансового приложения подрывает доверие.
- **Шифровать ключ своим AES поверх prefs** — ключ шифрования негде хранить, кроме тех же prefs: безопасность-театр.
- **SQLCipher для всей базы** — правильный, но отдельный и больший шаг; не заменяет keychain для секретов и остаётся в планах (ADR-0008).
