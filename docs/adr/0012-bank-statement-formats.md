# 0012. Форматы банковских выписок: CSV + OFX + XLSX

Дата: 2026-08-24
Статус: accepted

## Context

Банки выгружают выписки в разных форматах: российские — чаще CSV и Excel (XLSX), международные и агрегаторы — OFX (Open Financial Exchange). Импорт только CSV заставляет пользователя конвертировать файлы вручную.

## Decision

Все форматы приводятся к одной таблице строк и попадают в существующий пайплайн импорта (автомаппинг колонок → предпросмотр → дедупликация по контент-хэшу):

- **Определение формата по содержимому** (`detectFormat`): zip-сигнатура `PK` → XLSX, `<OFX`/`OFXHEADER` → OFX, иначе CSV/TXT.
- **OFX** — собственный парсер SGML/XML-блоков `STMTTRN` (DTPOSTED/TRNAMT/NAME|MEMO); формат стандартный, полноценная XML-библиотека не нужна.
- **XLSX** — собственный минимальный ридер первого листа поверх пакета `archive` (уже в транзитивных зависимостях): sharedStrings, inline-строки, числа; серийные даты Excel конвертирует общий разборщик дат.

Готовые пакеты (`excel`, `spreadsheet_decoder`) не используются: их зависимости конфликтуют с генераторами брендинга, а нужен только read-only первого листа.

## Consequences

- Один пайплайн импорта для всех форматов; новые форматы добавляются новым парсером «файл → таблица строк».
- XLSX-ридер намеренно минимален: формулы, стили и несколько листов не поддерживаются — банковские выписки этого не требуют. Если потребуется больше — пересмотреть пакетный вопрос отдельным ADR.
- PDF-выписки добавлены отдельным шагом (v1.2): собственный извлекатель текста (`lib/data/pdf_text.dart`) и разборщик выписки по счёту карты СберБанка. Форматы PDF банк меняет несколько раз в год, поэтому разборщик держится на корпусе фикстур, а незнакомая вёрстка уходит в общую эвристику «строка с датой и суммой».
