# 0008. Приватность и синхронизация: PIN локально, sync через облако пользователя

Дата: 2026-08-24
Статус: accepted

## Context

v0.7 роадмапа: защитить данные от постороннего с устройством в руках и дать доступ к данным с нескольких устройств. Numo — приложение без своего бэкенда (единственный сетевой вызов — курсы ЦБ, ADR-0007), и заводить сервер ради синхронизации значит взять на себя хранение чувствительных финансовых данных пользователей.

## Decision

**Блокировка приложения.** PIN-код, хранится только соль + SHA-256(соль+PIN) в shared_preferences (пакет `crypto`, first-party Dart team). Экран блокировки — при каждом запуске, если PIN установлен. Биометрия (local_auth) добавится отдельным шагом после ручной проверки на реальных iOS/Android-устройствах: CI не собирает мобильные платформы, вслепую менять MainActivity и plist рискованно.

**Синхронизация — файл в облаке пользователя, а не свой бэкенд.** Пользователь указывает папку, которую синхронизирует его собственный инструмент (Яндекс.Диск, Dropbox, Syncthing…). Numo после каждого изменения пишет туда полный бэкап `numo-sync.json` (формат бэкапа v2), а при запуске сравнивает метку `exportedAt` файла со своей последней записью: если файл новее — предлагает принять данные с другого устройства. Модель «последняя запись побеждает», без построчного merge — честно и предсказуемо для одного пользователя с несколькими устройствами.

**E2E-шифрование** в этой модели не требуется: файл не покидает личное облако пользователя, которому он уже доверяет свои файлы. Опциональное шифрование архива паролем — возможное развитие, если появится запрос.

## Consequences

- Нет своего сервера — нет затрат, аккаунтов и ответственности за чужие финансовые данные.
- Одновременное редактирование на двух устройствах разрешается в пользу последнего записавшего; для персонального финансового трекера это приемлемо.
- Файловый sync недоступен на web (нет доступа к папкам) — там остаётся ручной экспорт/импорт.
- PIN защищает от постороннего с устройством, но не шифрует базу; шифрование хранилища (SQLCipher) — отдельное будущее решение.

## Alternatives considered

- **Свой бэкенд с E2E** — максимум контроля, но сервер, аккаунты, деньги и юридическая ответственность; несоразмерно продукту.
- **CloudKit/Google Drive API** — нативные SDK на каждую платформу, шесть реализаций и OAuth; папка пользователя покрывает то же дешевле.
- **CRDT/пооперационный merge** — правильно в пределе, но для одного пользователя LWW-файла достаточно; можно вернуться при реальных конфликтах.
