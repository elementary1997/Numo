# 0006. Хранилище переведено на drift/SQLite

Дата: 2026-08-24
Статус: accepted (реализует план из ADR-0003)

## Context

ADR-0003 фиксировал shared_preferences как временное хранилище MVP с планом миграции на drift. v0.3 роадмапа — момент этой миграции: впереди бюджеты, счета и импорт выписок, которым нужен настоящий SQL.

## Decision

- Единая база `NumoDatabase` (drift) с таблицами `TransactionRows` и `CategoryRows`; доменные модели остаются отдельными от строк таблиц.
- Платформы закрывает `drift_flutter`; на web используется sqlite3 WASM: файлы `web/sqlite3.wasm` и `web/drift_worker.js` закоммичены в репо и должны соответствовать версиям пакетов `sqlite3`/`drift` из pubspec.lock.
- Репозитории сохраняют прежний синхронный интерфейс через write-through кэш: чтение из памяти, запись транзакцией в базу. UI и провайдеры не изменились.
- Миграция происходит однократно при первом открытии: если таблица пуста и стоит legacy-JSON в shared_preferences — данные переносятся; на чистой установке сидируются демо-данные/встроенные категории. Флаги `numo.*.migrated-to-drift.v1` защищают от повторного сидирования после полного удаления данных пользователем.

## Consequences

- Данные переживают годы записей; путь к индексам и SQL-выборкам открыт (следующий шаг — перенести фильтры поиска в запросы).
- `saveAll` пишет весь набор целиком — на текущих объёмах это миллисекунды; при переходе на пошаговые операции интерфейс репозитория расширится (add/update/remove) без изменения UI.
- Схема версионируется `schemaVersion`; изменения схемы — через drift-миграции, а не смену ключа.
- В тестах база создаётся как `NumoDatabase(NativeDatabase.memory())` — нужна системная libsqlite3 (есть на Ubuntu-раннерах и в WSL).
