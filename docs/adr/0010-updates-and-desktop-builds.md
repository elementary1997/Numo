# 0010. Обновления через GitHub Releases и автосборки desktop

Дата: 2026-08-24
Статус: accepted

## Context

Приложение распространяется desktop-сборками из GitHub Releases; пользователю нужен понятный путь узнать о новой версии и получить её. Полноценные авто-апдейтеры (Sparkle, Squirrel, MSIX-каналы) требуют подписи и платформенной инфраструктуры, которой пока нет.

## Decision

**Канал обновлений — GitHub Releases.** Приложение раз в сутки (кэш в shared_preferences) спрашивает `api.github.com/releases/latest`, сравнивает semver-тег с собственной версией (`package_info_plus`) и ненавязчиво предлагает открыть страницу релиза (`url_launcher`) — скачивание и установка остаются за пользователем. Это второй разрешённый сетевой вызов после курсов ЦБ (ADR-0007): анонимный GET без токенов; в настройках есть выключатель автопроверки, ручная проверка доступна всегда. Ошибки сети молча игнорируются — офлайн ничего не ломает.

**Автосборки.** Каждый push в `main` собирает Windows- и macOS- (и Linux-) сборки в GitHub Actions и публикует их артефактами с коротким SHA (14 дней хранения) — свежую сборку можно взять не дожидаясь релиза. Релизы по тегу `vX.Y.Z` работают как раньше (`release.yml`).

Процесс выпуска описан в `docs/releasing.md`.

## Consequences

- Пользователь узнаёт о новой версии в приложении, но устанавливает её сам — честный компромисс без подписанных инсталляторов.
- Проверка обновлений на web не показывается (там всегда свежая сборка по URL).
- Когда появятся подписи (notarization, MSIX), поверх этого же канала можно надстроить полноценный авто-апдейт — отдельным ADR.

## Alternatives considered

- **Sparkle/Squirrel/auto_updater** — настоящий авто-апдейт, но требует подписанных бинарей и appcast-инфраструктуры; преждевременно.
- **Магазины (MS Store, App Store)** — решают обновления сами, но это путь v1.0-публикации с аккаунтами, а не замена каналу для прямых сборок.
- **Молчаливое скачивание бинаря приложением** — рискованно и неожиданно для пользователя; открытая страница релиза прозрачнее.
