# 0003. Хранилище MVP: JSON в shared_preferences, миграция на drift позже

Дата: 2026-08-24
Статус: accepted

## Context

MVP хранит сотни, максимум тысячи операций локально. shared_preferences работает на всех шести платформах из коробки; SQLite (drift) требует кодогенерации и платформенных нюансов, замедляя первый релиз.

## Decision

Хранить операции как один JSON-массив в shared_preferences под версионированным ключом `numo.transactions.v1`. Весь I/O — только через `TransactionsRepository`, чтобы замена хранилища не трогала состояние и UI. Переход на drift запланирован, когда появятся объёмные данные или сложные выборки (бюджеты, несколько счетов, поиск).

## Consequences

- Простота и нулевые зависимости платформ; полная перезапись массива на каждое изменение — приемлемо на малых объёмах.
- Изменение схемы JSON требует поднять версию ключа и написать миграцию — иначе тихая потеря данных пользователя.
- Интерфейс репозитория — контракт для будущей drift-реализации.

## Alternatives considered

- **drift (SQLite) сразу** — правильно в пределе, но кодогенерация и настройка ffi на desktop задержали бы MVP.
- **Isar/Hive** — Isar в неопределённом статусе поддержки; Hive-боксы не дают SQL-выборок, а преимущества перед JSON на этих объёмах нет.
- **Файл JSON через path_provider** — то же самое, но с ручной работой с файловой системой и без атомарности shared_preferences.
